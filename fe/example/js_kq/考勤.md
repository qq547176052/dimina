# 考勤系统改造规划

> 目标：把现有"人脸抓拍 + 人脸库"小程序，彻底改造为**考勤系统**。
> 旧 tab（抓拍记录 / 人脸库）全部弃用删除，新 tab 仅保留 **考勤统计**、**人员管理**。
> 后端现状：钉钉 Stream 打卡 / 摄像头抓拍分发均已落库 `dd_9_attendance`（含去重）；钉钉人员表 `dd_7_dingtalk_members` 已存在，PC 端 `face_dingtalk_staff.html` 已通过 `/dd/dingtalk-staff` 接口管理。
>
> **实施状态（2026-08-03）：已落地。**
> - 后端：`config/appsql/dd_9_考勤.go` 新增迟到阈值常量、`F计算迟到等级`、`F考勤统计`，扩展 `F分页查询钉钉考勤_扩展`；新增 `dd/考勤查询.go`（`F考勤记录查询`/`F考勤统计`/`F考勤图片`），已在 `main.go` 注册。
> - 小程序：`app.json` 仅剩 `kaoqin`/`staff` 两 tab；`utils/api.js` 提供 `attendance`/`staff` 封装；新建 `page/kaoqin`（日/周/月统计卡 + 升序列表 + 迟到黄/红标记）、`page/staff`（对标 PC 字段 + 点击进个人明细）；删除 `page/index`/`page/face`/`page/max_image`；`login.js` 首页改为 `/page/kaoqin/kaoqin`。

## 一、整体架构

```
摄像头抓拍 ──┐
             ├─→ dd 后端 ──→ dd_9_attendance（考勤表，source=钉钉推送/摄像头抓拍）
钉钉打卡事件 ┘        │
                      │  HTTP 查询/统计接口（需新增）
                      ▼
            小程序（考勤统计 tab / 人员管理 tab）
```

关键事实：
- 考勤数据已双来源落库，前端只需查 `dd_9_attendance` 一张表。
- 人员管理复用钉钉人员：`dd_7_dingtalk_members` + 现有 `/dd/dingtalk-staff` 接口（参考 PC `face_dingtalk_staff.html`）。
- 迟到阈值需配置化（先后端常量，二期可后台配置）。

- `page/max_image` 删除（不再跳转大图）。
- 保留 `page/login`（登录态校验，沿用现有 `确保Token` 逻辑）。

### 2.2 考勤统计页 `page/kaoqin/kaoqin`

复用现有 `page/index/index.js` 的骨架（`确保Token` 校验、`mixin/common`、下拉刷新、上拉加载、筛选抽屉手势），语义改为考勤。

#### 顶部：周期切换 + 统计卡
- 周期 Tabs：**日 / 周 / 月**（默认"日"）。
- 日期选择：日统计选具体日期（默认今天）；周统计选某一周（默认本周）；月统计选某月（默认本月）。
- 统计卡（调 `attendance.summary`）：
  - **应到人员**：取自 `人员管理`的应到名单总数（或统计周期内能考勤的总人数）。
  - **未到人员**：应到 − 实到（实到=该周期有打卡记录且去重的人数）。
  - **迟到人数**：按迟到阈值统计。
  - **严重迟到人数**：按严重迟到阈值统计。

#### 列表：考勤明细（按打卡时间排序）
- 排序：**先到 → 最晚到**（升序，与现有 index 倒序相反，需新增参数或后端支持）。
- 列表项字段：姓名、打卡时间文本、打卡地点（Address）、来源标签（钉钉推送/摄像头抓拍，配色区分）、位置结果（Normal 绿 / NotInRange 红）。
- **迟到标识**：
  - 超过"迟到阈值"（如 09:00 后打卡）→ 标记**黄色**（轻微迟到）。
  - 超过"严重迟到阈值"（如 09:30 后）→ 标记**红色**（严重迟到）。
  - 标记在姓名/时间前以色块或图标呈现；阈值由后端返回（见 §三 2.3 `lateLevel`）。

#### 筛选抽屉（复用现有手势）
- 姓名（模糊）
- 周期已被顶部 Tabs 替代，抽屉只留：姓名、来源（全部/钉钉推送/摄像头抓拍）、位置结果（全部/正常/异常）。

### 2.3 人员管理页 `page/staff/staff`

直接对标 PC `face_dingtalk_staff.html` 的表格 + 同步能力，适配小程序列表。

- 列表字段（与 PC 一致）：序列号(id)、姓名(name)、别名(alias)、部门(department)、工号(workid)。
- 顶部工具栏：姓名搜索框 + "同步"按钮（触发 `/dd/face-library/sync`，可选，一期可隐藏）。
- 操作：点击某人员 → 进入其"个人考勤明细"（跳转 `kaoqin` 并带 `userId`/`name` 筛选，复用统计页列表）。
- 编辑别名：一期小程序端**只读**展示（别名编辑保留在 PC 端，避免重复实现表单弹窗）；二期再加小程序内编辑。
- 分页：沿用 `unwrapList` 的 page/pageSize/total 模式 + 上拉加载。

## 三、后端（需新增 / 扩展接口）

### 3.1 人员管理接口（已存在，直接复用）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/dd/dingtalk-staff` | 钉钉人员分页（name 模糊、page/pageSize），返回 `list[ {id,name,alias,department,workid} ]` + total |
| PUT | `/dd/dingtalk-staff/:id` | 编辑别名（PC 端用，小程序一期只读） |
| DELETE | `/dd/dingtalk-staff/:id` | 删除（PC 端用） |
| POST | `/dd/face-library/sync` | 发起钉钉→本地→摄像头同步（PC 端用） |

> 小程序 `人员管理` tab 一期只调 `GET /dd/dingtalk-staff`。

### 3.2 考勤统计接口（需新增）

文件建议：`code_sh/dd/ddApi/考勤查询.go`（新增，独立于 Stream 订阅）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/dd/attendance` | 考勤记录分页（支持升序，供"先到→最晚到"） |
| GET | `/dd/attendance/summary` | 考勤统计（日/周/月，含应到/未到/迟到/严重迟到） |
| GET | `/dd/attendance/image` | 头像/全景照代理（复用 `/dd/face-records/image` 逻辑，按 face_url/bg_url 相对路径取图） |

### 3.3 `GET /dd/attendance` 入参（Query）

复用并扩展 `F分页查询钉钉考勤`（需补 `userId` / `source` / `order`）：

| 参数 | 类型 | 说明 |
|------|------|------|
| page / pageSize | number | 分页 |
| name | string | 姓名模糊 |
| userId | string | 工号精确（人员管理跳转个人明细用） |
| source | string | `钉钉推送` / `摄像头抓拍` |
| startTime / endTime | string | `yyyy-MM-dd HH:mm:ss` |
| order | string | `asc`（先到→最晚到）/ `desc`（默认倒序） |

响应（对齐 `unwrapList`）：

```json
{
  "code": 200,
  "success": true,
  "data": {
    "list": [
      {
        "id": 1,
        "name": "张三",
        "userId": "103748...",
        "checkTime": 1785671480000,
        "checkTimeText": "2026-08-02 13:24:50",
        "address": "骏盛智造五楼",
        "deviceName": "骏盛智造五楼",
        "locationResult": "Normal",
        "source": "钉钉推送",
        "faceUrl": "/abs/path/face.jpg",
        "bgUrl": "/abs/path/bg.jpg",
        "lateLevel": 0
      }
    ],
    "total": 156,
    "page": 1,
    "pageSize": 20
  }
}
```

`lateLevel`：0 正常 / 1 迟到(黄) / 2 严重迟到(红) —— 由后端按打卡时间与阈值算（见 §3.5）。

### 3.4 `GET /dd/attendance/summary` 入参 / 响应

入参：

| 参数 | 类型 | 说明 |
|------|------|------|
| type | string | `day` / `week` / `month`（默认 `day`） |
| date | string | 基准日期 `yyyy-MM-dd`（默认今天；周/月按此日期归属） |
| name | string | 可选姓名模糊（个人维度统计） |

响应：

```json
{
  "code": 200,
  "success": true,
  "data": {
    "type": "day",
    "date": "2026-08-02",
    "rangeText": "2026-08-02 00:00 ~ 23:59",
    "shouldArrive": 86,        // 应到人数（取自人员管理总数 / 可考勤人数）
    "arrived": 42,             // 实到人数（周期内去重 userId 有打卡）
    "notArrived": 44,          // 未到 = shouldArrive - arrived
    "late": 3,                 // 迟到(黄) 人数
    "seriousLate": 1,          // 严重迟到(红) 人数
    "bySource": { "钉钉推送": 30, "摄像头抓拍": 56 },
    "lateThreshold": "09:00",
    "seriousLateThreshold": "09:30"
  }
}
```

> `shouldArrive` 取值策略：一期取 `dd_7_dingtalk_members` 总人数（忽略请假/排班）；二期接钉钉考勤组排班 API 精确应到。

### 3.5 迟到阈值（后端常量，先硬编码可配）

## 四、小程序 API 封装（utils/api.js 扩展）

新增 `attendance` 与 `staff` 两个命名空间，复用 `unwrapList`：

```js
const attendance = {
  // 列表（支持 order=asc 先到→最晚到）
  list(params = {}) { return request({ url: '/dd/attendance', method: 'GET', params }).then(unwrapList) },
  // 统计
  summary(params = {}) { return request({ url: '/dd/attendance/summary', method: 'GET', params }) },
  // 头像/全景照地址（相对路径拼 BASE，同 faceRecords.imageUrl）
  imageUrl(filePath) {
    const p = String(filePath || '').trim()
    if (!p || /^https?:\/\//i.test(p)) return p
    return `${BASE}/dd/attendance/image?path=${encodeURIComponent(p)}`
  },
}
const staff = {
  // 人员列表（复用 unwrapList）
  list(params = {}) { return request({ url: '/dd/dingtalk-staff', method: 'GET', params }).then(unwrapList) },
}
module.exports = { BASE, authHeaders, setToken, faceRecords, faceLibrary, attendance, staff }
```

> 注：改造后 `faceRecords` / `faceLibrary` 不再被页面使用，可保留待删（按"无关脚本及时删除"原则，确认无引用后删除）。
